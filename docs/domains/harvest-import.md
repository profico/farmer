# The Harvest import

An admin drops the Harvest CSV exports on Settings → Import (`settings/import.tsx`); `harvest-import.service.ts` writes them. The design and the owner's decisions are in `docs/plans/harvest-import.md`.

- **Parsing and planning run in the browser, in a Web Worker** (`components/import/harvest.worker.ts`, on `packages/core/src/lib/harvest/`). A real export is ~240k rows: the Worker keeps the day chunks and the page holds only the review, because a structured clone of every row on each re-plan would freeze the tab. The server takes the plan in steps — `start` (clients, tasks, people, projects), `importDays` in chunks of `HARVEST_CHUNK_MAX_ROWS`, `removeDays`, `finish` — and every step is safe to repeat, so "Retry" continues from the cursor. `start` is made repeatable by a run id the browser generates once per attempt: a second `start` with the same id returns the run it already created.
- **The unit is a person-day, compared by digest.** A day already imported unchanged is skipped, a changed one replaced, and a day somebody edited here is **kept**, never overwritten. A day the file no longer has is removed only when the admin confirms the file is a full export. That is what makes dropping the same files twice a no-op.
- **`finish` moves `automationLockedThrough` to the day before the cutoff**, so no engine writes into imported history, and prefills the hour fund for every year with history, because Expected needs it.
- **A guessed email makes an archived person with `emailUnconfirmed`.** A Harvest person with no address gets `first.last@domain`; they cannot sign in until an admin confirms the address on People (Restore for an archived person, "Confirm email" for an active one), since a wrong guess is otherwise somebody else's login. An address the admin **typed** on the review screen is not a guess: it counts as confirmed (`emailConfirmed` on the person plan).
- **Undo removes exactly what `importMapping` says the run created** — and only for the latest run. It does not restore days the run replaced, does not move the lock back, and refuses outright once a created person has signed in or an entry made here uses a created row.
- **Two questions block the plan until the admin answers them on the review screen**, because neither has a safe default:
  - **Names that differ only in accents or punctuation** ("Tin Primjerić" / "Tin Primjeric") — one person or different people (`choices.duplicates`, keyed on the ASCII fold). "One person" merges the spellings into the chosen one, and the other gets an `alias` person plan: `start` maps it to the same user, not `created`, so undo removes only the mapping. A group whose every spelling an earlier run mapped is not asked again — one user is one person, two users stay two.
  - **Negative correction rows** — `subtract` takes each off the row with the same person, day, project, task and overtime flag (an exact match first, then the largest), rounds the rest again and gives it a new `…:net` key; `leave_out` imports the other rows as they are. The keys differ, so changing the answer later replaces those days on the next run. A correction with no row big enough to take from stays under "needs attention" either way.
- Rows of two source people who are one user here (an alias, or two names matched to one member) are one person-day in the plan, as `importDays` groups them, so the digest covers the same rows as the stored one.
