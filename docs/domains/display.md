# Theme, Display preferences and popups

How the web app draws light and dark, the per-device Display preferences and the anchored popups. Read this before you change, in `apps/web/src/`, `styles.css`, `lib/theme.ts`, `lib/display-prefs.ts`, `lib/popup-layer.ts`, `apps/web/scripts/check-palette-contrast.ts` or a popup component.

**Light/dark is `data-theme` on `<html>` and nothing else.** Both palettes are written out in `styles.css`; `lib/theme.ts` owns the attribute and the DOM is the state — no provider. `themeInitScript` runs inline in `<head>` (`__root.tsx`) before React exists, because the choice lives in localStorage and applying it on hydrate flashes the light palette; that mismatch is why `<html>` carries `suppressHydrationWarning`. No stored choice follows the OS. The calendar's category tints (`lib/category-colors.ts`) are light washes computed in JS and read bright in dark mode. **Preferences → Display is the same design**, per device and off by default: "High contrast" (`data-contrast="high"`), "Boring font" (`data-font="sans"`), "Less movement" (`data-motion="reduce"`) and "Compact tables" (`data-density="compact"`), all owned by `lib/display-prefs.ts` and set by `displayInitScript` in the same `<head>` script. High contrast draws every mark harder on the SAME paper — the three surfaces and `--fg` do not move, and `--mut`, `--faint`, `--acc`, the status colors, the chart earths, the two hairlines and `--text-sel` each move in OKLCH lightness alone until they reach 7 against the worst surface (`--faint` answers to 4.5, so it stays a step quieter than `--mut`). Focus is one `*:focus-visible` outline rule rather than a token, because the house ring pattern writes its opacity into the class at about thirty call sites. Every number is fitted by `scripts/check-palette-contrast.ts` (`bun run check:palette`), which sweeps both contrast levels across the wheel — change a lightness in `styles.css` and change it there. Boring font re-points `--serif`, so a new display rule must read `var(--serif)`, never name Instrument Serif. Less movement ends every CSS animation and transition at once (`styles.css`) and sets Motion's `MotionGlobalConfig.instantAnimations`, so completion callbacks still fire but no animation is seen. Compact tables sets `--table-cell-py`, which only `TableCell`'s default padding reads — a cell with its own `py-*` keeps it.

## Popups

**An anchored popup is portalled into `#popup-layer`, never into `<body>`.** Preferences → Display → Scale is `zoom` on `<html>`, and a popup is placed by arithmetic on `getBoundingClientRect` — viewport pixels — so a popup drawn inside that zoom has every offset multiplied a second time and lands a whole scale further down the page. `lib/popup-layer.ts` is one element that takes the zoom back off, and `.popup-scaled` on the popup puts it back on so the popup is still drawn at the app's size; `--popup-anchor-width` and `--popup-available-height` are the same two lengths already divided, and a popup reads those and never Base UI's own. The zoom has to stay OFF the positioner: Floating UI reads the scale of the element it is placing and changes the pixels it answers in to match, so a zoomed positioner moves the error rather than removing it. At 100% none of it does anything, which is why a new popup that skips it looks correct on the machine it was written on.
