# apps/web

The TanStack Start / React app, and the production host that serves it. Read the
root `CLAUDE.md` first for the commands and the lint rules.

```bash
bun run build            # vite build → dist/{client,server}, then prunes dist/client
bun run start            # NODE_ENV=production bun run server.ts — the production host
bun run generate-routes  # tsr generate — regenerates routeTree.gen.ts
```

## Layout

- `src/routes/` — TanStack Router file-based routing.
  - `$orgSlug/route.tsx` is the org-scoped layout: its `beforeLoad` resolves the session, the organization and the caller's role in ONE server call (`enterOrganization`) alongside `getPublicAppConfig`, and redirects out if any check fails — every nested route inherits that guard. `enterOrganization` repoints the session only when the active org actually differs.
  - Under it: `index.tsx` (home: today, plus week and month targets), `time/` (a `route.tsx` layout with the targets strip and the unfiled banner, then `index`/`week`/`month`), `projects/` (the list, and `$projectId/` with `index`/`team`/`settings`), `reports.tsx`, `audit-log.tsx` (admins only, a sidebar row under Reports; see `docs/domains/audit-log.md`), `assistant.tsx`, and `settings/` (an `index.tsx` hub plus organization, members, my-schedule, clients, tasks, recurring-blocks, holidays, hour-fund, reminders, import, integrations, ai (the assistant's settings and its usage), preferences, `webhooks/` — the endpoint list plus one endpoint's delivery log — and the Infrastructure group, shown only to a platform admin: platform-admins plus `instance/` (sign-in, email, storage, integrations, features — one page per section of `INSTANCE_SETTINGS`, all drawn by `components/instance-settings.tsx`; see ADR 0004)).
  - Outside it: `index.tsx` (a redirect into the workspace; the public pages live in `apps/site`, see `docs/domains/deployment.md`), `login.tsx`, `choose-organization.tsx` (the workspace chooser for a link such as `/:org/settings`; see `docs/domains/authentication.md`), `accept-invite/$invitationId.tsx`, `no-access.tsx`, `device.tsx` (approves a CLI login) and `cli/` (the install scripts and binary downloads).
  - Server routes: `api/auth/$.ts` (better-auth), `api/login.ts`, `api/mcp-login.ts`, `api/github/setup.ts`, `api/slack/callback.ts`, `api/files/$.ts`, `api/assistant/stream.ts`, `api/mcp/$orgSlug.ts`, `[.]well-known/oauth-*.ts`, `api/v1/projects` + `api/v1/time-entries` (cookie-authed REST reads), and `api/v1/{meta,me,session}`, `api/v1/me/devices` (the mobile app's phone, see `docs/domains/mobile.md`) + `api/v1/orgs/$orgSlug/*` (the CLI's API). `api/v1/openapi[.]json.ts` serves the OpenAPI document that `lib/openapi.ts` builds, and `api-docs.tsx` renders it with Scalar. **A new `api/v1` route needs an entry in `OPERATIONS`** — `lib/openapi.test.ts` fails until the two lists match, and each response schema there is checked against its `@farmer/core/api` type at compile time. That API takes two bearer credentials — a device-flow session token and a personal API token (`fmr_…`, Preferences → API tokens, `components/api-tokens-settings.tsx`); `docs/domains/api-tokens.md` has the rules, including the read-only 403 in `serve` and the `session` scheme that lets `/api-docs` send requests as the signed-in reader (`?org=` on the OpenAPI route; never add CORS headers to `api/v1`). All of that auth lives in `server/api-auth.ts` — deliberately NOT `server/auth.ts`, see the client-bundle rule below.
  - `reports.tsx` is the shell. Its four tabs — Time, Overtime, Tracking (`compliance`) and Absence — are declared in `components/reports/search.ts` and live in `components/reports/`. `periodSearch` there is shared with the project page.
- `src/server/` — thin `createServerFn` wrappers, one file per aggregate, mirroring `services/`. **Auth is attached via middleware** (`sessionMiddleware` / `orgMiddleware` / `orgAdminMiddleware` from `server/auth.ts`), read from the handler's `context` — never by calling `requireOrgContext()` inline, so the protection is part of the function's declared shape. `auth.ts` itself is the only place the bare helpers are called, because route `beforeLoad`s need them. `orgMiddleware` re-checks membership inside its `.server()` callback rather than in a shared helper: a top-level function body in `auth.ts` ships to the browser, so a deferred `import("@farmer/core/services")` there becomes a real client chunk.
- `src/queries/` — TanStack Query `queryOptions` factories, one per aggregate; loaders prefetch, components read via `useSuspenseQuery`. **Every key names its organization**: factories take the slug first (`timeEntriesRangeQuery(orgSlug, from, to)`) and spread their root from `queryKeys(orgSlug)` in `queries/keys.ts`; invalidations name the same root. Components get the slug from `useOrgSlug()`, loaders from `params.orgSlug`. Never write a bare `queryKey: ["…"]` literal and never drop the org — an org-blind key is an answer from the previous workspace. Server functions are deliberately NOT generated from a shared declaration — see `docs/adr/0001-no-server-function-generator.md`.
- `src/components/ui/` — shadcn on **Base UI** (`@base-ui/react`), not Radix (`components.json` style is `base-nova`). Composition uses the `render` prop, not `asChild`. The project picker (grouped by client) and task picker (grouped by `taskGroup`) are in `components/pickers/`. The task picker leaves out the tasks the person switched off (`pickers/your-tasks.tsx`, also Preferences → Your tasks), search included, except the task already chosen and Recent; its grouped list ends in Edit list.
- **An eyebrow carries live context or a way back** — a date, a period, a count, a return link (`SettingsEyebrow`, the project pages' back link). Never a static label that repeats the title or the page; on a `PageHeader`, leave `eyebrow` out instead.
- **Table search filters the view only.** `@farmer/core/lib/search` (`matchesSearch`: case- and accent-insensitive, any word in any field) and `components/ui/search-input.tsx` back every search box. **Totals and stats are computed over the full dataset, never over the filtered rows** — a total that tracked the search box is a wrong number, not a filtered one.
- **The stopwatch is mounted in three places** — the sidebar control card (`components/time/timer-row.tsx`), the button beside "Log time" on the Day view, and the cap on Settings → My schedule. Both stop controls HOLD the clock before they open the Log dialog, which is why that dialog's third button says Resume. All three read ONE query through `hooks/use-timer.ts`, so no two surfaces can disagree about what is running. The Start button on each entry row (it continues the entry) is not a fourth surface: the list reads the timed entry id once through `useTimedEntryId` in the same file and passes it to each row as a prop, so no row subscribes to the timer. Read `docs/domains/timer.md` before changing any of them.
- **`lib/entry-options.ts` remembers per device** (localStorage) the last project and task per org and per dialog, and the `fillsDay`/`overtime` options per project and task. Repeat is deliberately not remembered.
- **The week starts on the organization's `weekStartsOn`** (`organization.week_starts_on`, 1 = Monday by default, 0 = Sunday; Settings → Organization). `startOfWeekKey` and `resolveReportPeriod` take it as a required argument, so a new caller cannot forget it silently. Pages read it from the `/$orgSlug` route context (`useWeekStartsOn`, `useWeekdays`), services from `ctxWeekStartsOn`, and the CLI from `whoami`. Stored weekday numbers stay `Date#getDay()`'s (Sunday = 0); only the order a week is drawn in changes.
- **Light/dark is `data-theme` on `<html>` and nothing else.** `lib/theme.ts` owns the attribute and the DOM is the state — no provider. `themeInitScript` runs inline in `<head>` (`__root.tsx`) before React exists, which is why `<html>` carries `suppressHydrationWarning`. Preferences → Display is the same design, per device, owned by `lib/display-prefs.ts`. Read `docs/domains/display.md` before you change a colour, a Display preference or a popup. The rules:
  - Change a lightness in `styles.css` and change it in `scripts/check-palette-contrast.ts` too (`bun run check:palette`).
  - A new display rule reads `var(--serif)`. Never name Instrument Serif.
  - Compact tables sets `--table-cell-py`, which only `TableCell`'s default padding reads.

## The client-bundle rule

**Critical, non-obvious rule:** never put a static top-level `import ... from "@farmer/core/db"` / `"/auth"` / `"/services"` in any route or `src/server/*.ts` file. `postgres` touches `Buffer` at module scope, which crashes hydration in the browser — silently: forms fall back to native submission instead of throwing. Always import inside the handler body:
```ts
export const createTimeEntry = createServerFn({ method: "POST" })
  .middleware([orgMiddleware])
  .validator(createTimeEntryInput)
  .handler(async ({ data, context }) => {
    const { timeEntriesService } = await import("@farmer/core/services");
    return timeEntriesService.create(context.ctx, data);
  });
```
This is also why `requireOrgAdmin` routes through the `getMyRole` server function instead of importing services directly — it's called from a route `beforeLoad`, which also runs client-side during SPA navigation.


## The host

Dev is `vite dev`, which never loads `server.ts`. **Production is a Bun-native host, not Nitro/srvx**: `vite build` emits a web-standard `{ fetch }` handler with nothing to serve it, so `apps/web/server.ts` (TanStack's start-bun reference) brings its own `Bun.serve` — static-asset preloading plus the in-process schedulers. The image, the jobs and the env flags are in `docs/domains/deployment.md`.

**`Bun.serve` carries `idleTimeout: 255`, Bun's maximum, and it is load-bearing.** The default is 10 seconds, and Bun enforces it by closing the socket with an empty reply while the handler keeps running. A server function that works longer than that — "Re-match people" on Slack, a Harvest import step — then succeeds on the server while the browser gets an unreadable reply, which TanStack Start reports as the bare "Invariant failed". `vite dev` does not run `server.ts`, so this never reproduces locally. Work that can outlast 255 seconds belongs in a job, not a request.

**Every response gets baseline security headers** (`lib/security-headers.ts`) — a dynamic one in `server.ts`'s `/*` wrapper, a static asset in its own route handler, because the static routes answer before the wrapper: `frame-ancestors 'none'`, `nosniff` and a referrer policy. Not a full CSP, because the inline theme and PostHog scripts in `__root.tsx` would need hashes or a nonce first, and not HSTS, which belongs at the TLS edge. A header a route sets itself wins, which keeps `api/files/$.ts`'s `sandbox` policy whole. `vite dev` sends none of them.

## The API pipeline

A route built with `apiRoute` (`api/v1/orgs/$orgSlug/*`) or `userApiRoute` (`me`, `session`) runs one pipeline, `server/api-route.ts`. Some `api/v1` routes do not use it (for example `meta`, `openapi[.]json`, `me/devices` and the assistant's `messages` and `approvals`), so they get none of these guards. Read `docs/domains/rest-api.md` before you change it. The rules:

- The order is fixed: `CLI_ENABLED`, the per-address limit before any read, the `x-farmer-cli-version` check (426), the credential, the per-user and write limits, the Zod parse, the service call.
- Every exit runs through one `finish`, which sends one `api_request` event with the route TEMPLATE, never the slug or the row id.
- **Never add CORS headers to `api/v1`.** A write takes the session cookie only with `x-farmer-session: 1` and a same-origin proof (`cookieUser`, `provesSameOrigin`). A request that sent `Authorization` never falls back to the cookie.
- Errors map by class: `ZodError` and `DayCapacityError` are 422, `AccessError` 403. The message of a bare `Error` goes to the terminal. **Throw a subclass for anything that is not a sentence for the person.** `packages/core/src/lib/github-client.ts` throws bare `Error`s with URLs, and is safe only because no route reaches it.

## Gotchas

- **On farmer.profi.co, `/` is the public site, so web code never targets `/`; use `/_`.** A full-page load to `/` (a `callbackURL`, `window.location`, a `Response.redirect`, a server `redirect`) lands on the marketing page. Use `/_`, or `{ to: "/$orgSlug", params: { orgSlug: "_" } }`.
- **`vite build` can emit server code into `dist/client`, and `server.ts` serves everything it finds there.** A deferred `await import("@farmer/core/…")` in a client-reachable module is chunked by rolldown *before* the server-fn transform strips the handler, which leaves an orphan island (better-auth's config, the drizzle schema, services) published at `/assets/<hash>.js`. `apps/web/scripts/prune-client-assets.ts` runs as the second half of `bun run build`, deletes the island and prints what it removed. It currently prunes nothing; keep it anyway, because it is the detector. It computes reachability from what the server build can name and aborts rather than guess — don't "simplify" it into an unconditional delete, and don't drop it from the `build` script.
- **A tab opened before a deploy reloads once when a chunk is gone** (`lib/stale-chunk.ts`, the `/assets/*` route in `server.ts`). Read "A stale chunk after a deploy" in `docs/domains/deployment.md` before you change it. Never remove TanStack's `tanstack_router_reload:<message>` key, because it is TanStack's loop guard. There is deliberately no `vite:preloadError` handler: a reload there would drop the unsaved input of a person who only hovered a link.
- **A PostHog call in a child effect must not run before the client started.** React runs child effects before the effects of the parent, and `@posthog/react` starts its client in the effect of its provider, so a `capture`, `identify`, `register` or `captureException` in the first commit was dropped. `lib/posthog-client.ts` (`startPostHog`) starts the client during the render of `PostHogRoot` in the browser, and the provider gets it as `client`. Do not pass `apiKey` and `options` to the provider again. A flag hook (`useFeatureFlagEnabled` and the others) reads this started client in its first render, so its value can differ from the server render.
- Base UI shadcn components have runtime-only failure modes that typecheck/build/lint all miss: `<Button render={<Link/>}>` to a non-`<button>` element needs `nativeButton={false}` or it throws in the console; `<Select>` needs an `items={[{value, label}]}` prop or the trigger displays the raw value instead of the resolved label.
- **An anchored popup is portalled into `#popup-layer`, never into `<body>`** (`lib/popup-layer.ts`), and `.popup-scaled` goes on the popup. A popup reads `--popup-anchor-width` and `--popup-available-height`, never Base UI's own, and the zoom stays OFF the positioner. Preferences → Display → Scale is `zoom` on `<html>`; at 100% a popup that skips this looks correct. See "Popups" in `docs/domains/display.md`.
- **A component reads today through `useToday` (`hooks/use-today.ts`), never `dayKeyInTz(new Date())`.** The hook renders again at midnight in the organization timezone and when the tab wakes, so an open timesheet moves to the new day. A read in the render body is right only until midnight, and no test fails when it goes stale. Loaders, the API and the server read the clock directly; that is correct there.
- **A link or a navigation to a timesheet route builds its search with `dateSearch`, `weekSearch` or `monthSearch` (`lib/time-search.ts`), and sets `activeOptions={EXACT_LINK}`.** The helpers keep the current day, week and month out of the URL, so a bookmark of "today" stays live. A hand-written `search={{ date }}` puts today back into the URL, and nothing fails. Without `EXACT_LINK`, a link with an empty search counts as the current page on every timesheet page.
- Always verify interactive changes in a real browser, not curl/SSR output — the hydration crash described above passed every curl-based check while silently breaking every form in the app. No browser automation package is installed in the repo.
